# 安全、验证与失效降级

## 1. 安全目标

目标是尽早发现障碍、限制运动速度、在感知/定位/通信退化时进入可解释的停止或降级状态。Nav2 是导航框架，不是安全认证控制系统。

必须区分：
- 导航能力；
- 碰撞预防策略；
- 功能安全/急停能力；
- 四足本体稳定和跌倒保护。

这些能力需要不同的证据和测试。

## 2. 失效模式与应对

| 故障/退化 | 可能影响 | 建议行为 |
|---|---|---|
| LiDAR 超时/数据年龄过大 | 近场几何感知丢失 | 限速或停止，不允许 stale scan clearing |
| 双目同步失效/深度空洞增加 | 视觉深度不可信 | 将 stereo source 标记 unavailable；依赖其余经验证传感器或停车 |
| RTK 从 Fixed 降为 Float/Single | 全局位置精度下降 | 质量门控、降权/冻结 GNSS 更新；扩大不确定度和降速 |
| GNSS 丢失 | 户外长期漂移 | 短时依赖 local odom，超过许可漂移/时间后停车 |
| IMU/腿式 odom 失效 | 本体状态估计异常 | 停止 Nav2 运动命令，进入底层安全状态 |
| TF 断链/时间戳跳变 | 传感器不能正确变换 | source 置为不可用，禁止用错误坐标更新 costmap |
| Controller/Nav2 崩溃 | 速度命令中断/失控风险 | 底层 watchdog 使命令失效并停止 |
| Collision Monitor 崩溃 | 软件保护层丢失 | 命令 gateway 监控其心跳；策略应 fail-safe |
| 底层控制器断连 | 无法确认执行状态 | 硬件/底层 watchdog 停止；报告故障 |
| 机身跌倒/失稳 | 继续导航可能扩大伤害 | locomotion controller 优先安全姿态/停机，Nav2 任务中止 |

## 3. Collision Monitor 的角色边界

Nav2 Collision Monitor 可以绕过 costmap 和 planner，以新鲜的 LaserScan、PointCloud2、Range 或 costmap 等数据计算停止/减速区域，适合做额外的软件级碰撞预防层。

但它运行在普通计算平台上，不提供硬实时或安全认证保证。因此：
- 人员附近/公共空间要另做风险评估；
- 不将 Collision Monitor 当作符合安全等级的光幕或安全扫描器；
- 必须有独立硬件急停和底层命令 watchdog；
- 测试其自身节点退出、topic 超时、TF 不可用、传感器错误时的行为；
- 确认没有其他节点绕过该层直接向机器狗底层发布行走命令。

## 4. 速度和停车距离

停车距离不是只由传感器距离决定。需考虑：
- 机器狗当前速度、负载、地面摩擦和坡度；
- 检测/传输/计算/规划/执行延迟；
- 步态周期与控制器响应延迟；
- 机身和足端的运动范围；
- 地面滑移、制动能力和姿态稳定性。

不得用固定的“障碍距离阈值”代替停车距离测量。应在各速度、载荷、地面和坡度条件下实测停止时间和距离，并留足风险余量。

## 5. 分级验证

### 级别 0：静态数据与接口
- 所有驱动可启动、频率稳定、时间戳可信；
- TF 树正确，外参可复现；
- rosbag 可录制和回放；
- 节点重启不会产生 TF 多发布者。

### 级别 1：感知离线验证
- 深度误差、视差有效率；
- LiDAR 距离误差和扫描平面；
- 障碍物检测范围、召回率、误检率；
- 透明、反光、无纹理、弱光和运动模糊分组报告。

### 级别 2：状态估计验证
- local odom 连续性；
- yaw/roll/pitch 误差；
- RTK 质量切换；
- GNSS 遮挡、跳变和恢复；
- map→odom 修正是否导致 local controller 的速度突跳。

### 级别 3：仿真/硬件在环
- 全局规划、局部避障、重规划和恢复；
- 动态障碍突然出现；
- Collision Monitor stop/slowdown；
- cmd_vel adapter 限幅和 watchdog；
- 传感器断流/错误 TF/高延迟故障注入。

### 级别 4：封闭场地低速实机
- 遥控急停有效；
- 低速直行、转弯、倒退、障碍绕行；
- 传感器和控制节点异常时停止；
- 逐级提高速度前，必须审核停车距离和安全边界。

### 级别 5：受控户外
- RTK 固定解和差分质量；
- 遮挡/多路径/改正丢失和恢复；
- GNSS waypoint 转换；
- 不同地面材质、坡度和光照；
- 明确测试区域边界与现场安全人员。

### 级别 6：复杂地形与长期运行
- 台阶、坡道、沟槽、路沿和负障碍；
- 可通行性层与足端规划协同；
- 长时间热稳定、振动、网络和数据记录；
- 只有风险评估允许时才开展。

## 6. 必须记录的指标

- 传感器消息频率、丢帧率、时间戳 age、网络时延；
- TF lookup 成功率和变换延迟；
- local/global 位置误差、航向误差、协方差和 GNSS fix 状态；
- 障碍物检测召回率、精确率、首次发现距离；
- 感知到 costmap 延迟、costmap 更新率；
- controller 频率、命令延迟、速度/加速度；
- stop trigger 时间、停止距离、误停和漏停；
- CPU/GPU/内存/温度；
- 故障到停车的时间；
- rosbag、参数版本、模型版本和设备固件版本。

## 7. 实机测试安全门槛

开始移动测试之前，必须：
- 现场有物理急停/遥控停止手段；
- 机器狗被限制在封闭区域；
- 先验证底层 watchdog 与 stop API；
- 由人工监护，测试区无无关人员；
- 从站立/静止/极低速开始；
- 停车距离经过验证；
- 有条件地禁用自动恢复行为，避免恢复动作意外继续行走；
- 传感器状态与控制命令可实时监视。

任何一次无法解释的运动命令、定位跳变、障碍漏检或停止失败都应暂停提高测试级别，并形成问题记录。
