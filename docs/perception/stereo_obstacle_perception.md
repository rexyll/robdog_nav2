# 双目 RGB 障碍物感知

## 1. 为什么两台普通相机可提供深度

两台普通 RGB 2D 相机在固定基线、充分重叠视场和准确标定条件下，可组成被动双目系统。对左右图像中同一物点进行匹配，利用视差估计深度：

[
Z = \frac{fB}{d}
]

- (Z)：沿相机光轴的深度；
- (f)：像素单位焦距；
- (B)：左右光心基线；
- (d)：左右图像视差。

深度误差近似：

[
\sigma_Z \approx \frac{Z^2}{fB}\sigma_d
]

远距离深度误差会显著放大；近距离可能出现遮挡和视场重叠不足。相机基线、镜头焦距、分辨率、帧率和算法必须按目标距离范围设计。

## 2. 可承担的任务

- 较大障碍物几何位置与轮廓补充；
- 人体/车辆/箱体等目标检测后估计三维位置；
- LiDAR 未覆盖高度或角度内、但左右相机都能看到的障碍；
- 为动态障碍跟踪提供 RGB 外观特征；
- 在被动可见光条件适宜时，提供室外辅助深度。

## 3. 不可靠场景

| 场景 | 失效原因 | 补救策略 |
|---|---|---|
| 玻璃/透明塑料 | 左右视角透过/折射的背景不同，难以匹配玻璃表面 | LiDAR/其他传感器、玻璃区域语义提示，且要实测 |
| 镜面/高反光金属 | 不同视角反射不同环境内容 | 不将双目作为唯一传感器 |
| 大面积无纹理墙/箱子 | 左右图缺少可匹配特征 | 主动纹理/其他深度技术或 LiDAR |
| 极暗环境 | RGB 信噪比下降、曝光变长 | 补光/调整曝光或其他传感器 |
| 左右图不同步 | 动体像素运动污染视差 | 硬件同步、短曝光、时间诊断 |
| 快速运动/抖动 | 模糊、滚动快门和机身运动 | 全局快门、短曝光、IMU/odom 补偿 |
| 细线/极小物体 | 像素覆盖和视差置信度不足 | LiDAR/专用近距离传感器、风险规则 |
| 近距离遮挡边界 | 一侧看得到、另一侧被挡 | 遮挡置信度、与 LiDAR 互补 |

## 4. ROS 2 软件实现建议

优先评估 ROS 2 image_pipeline 的双目处理能力：
- camera driver 发布左右 image_raw 和 camera_info；
- message_filters 同步左右图像；
- stereo rectification；
- disparity computation；
- point cloud generation；
- 置信度、无效区域、范围和高度过滤；
- PointCloud2 接入 costmap。

另可评估 OpenCV StereoSGBM、RAFT-Stereo、CREStereo 等方案。选择不能只比较单帧精度，还要比较：
- 机器狗实际 CPU/GPU 上的帧率；
- 端到端感知延迟和抖动；
- 动态场景的同步鲁棒性；
- 近/中/远距离分段深度误差；
- 反光、无纹理、弱光、雨雾、振动条件；
- 许可、模型依赖、ARM 部署和维护成本。

## 5. 与 LiDAR 互补

建议保留两条独立的障碍流：
- `/lidar/obstacle_observations`：来源稳定、几何测距为主；
- `/stereo/obstacle_points`：经过置信度和无效深度过滤的视觉几何补充。

在 costmap 层组合，而不是先把两条数据无差别融合。这样更容易诊断某个障碍是来自哪种传感器，也能单独设置 source timeout、height range 和 clearing 行为。

## 6. 验证标定与深度精度

- 使用不同距离的标定板/已知尺寸平面；
- 统计深度 bias、RMSE、有效像素比例和置信度分布；
- 分段测试近/中/远距离；
- 测试温度变化、机身振动、轻微机械位移后的外参稳定性；
- 定期检查左右图 epipolar alignment；
- 标定文件必须版本化，记录相机序列号、镜头、分辨率、焦点/对焦状态和安装基线。

## 7. 不把 RGB 识别等同于安全检测

YOLO/SAM 或其他视觉模型提供类别/分割，不保证被遮挡物体有正确三维距离。碰撞防护仍依赖经过验证的几何源、独立 stop logic 和底层停止能力。
